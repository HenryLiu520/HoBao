# 货币显示规范（全局约定）

> 一次性定死，以后所有新界面都照这个来。定稿 2026-10-19

---

## 规则

| 场景 | 写法 | 例子 |
|---|---|---|
| **金额** | `代码 + 空格 + 数字` | `CNY 256.02` ／ `HKD 100.00` ／ `JPY 980` |
| **汇率公式** | 代码 | `1 CNY = 1.17 HKD` |
| **散文/说明** | 中文名（可以带括号补代码） | 「以人民币（CNY）为基准」 |
| **币种选择器** | 国旗 + 代码 | 🇨🇳 CNY |

**一句话：凡是"钱"，一律用 ISO 4217 三字母代码，不用符号。**

---

## 为什么弃用货币符号

改动前，同一个币种在界面上有 **三种写法**：

| 位置 | 写法 |
|---|---|
| 金额 | `CN¥256.02` |
| 币种芯片 | `CNY` |
| 汇率页 | `1 人民币 = 1.17 港币` |
| 列表副行 | `JP¥981 JPY` ← 符号和代码同一行重复 |

这就是"UI 不统一"的根源。

而且符号本身有两个硬伤：

1. **¥ 同时是人民币和日元**，$ 至少被 20 多个国家用
2. 我为了区分，自造了 `CN¥` / `JP¥` —— **这不是国际标准写法**，
   银行、交易所、任何财务系统都不这么写

代码没有歧义、全球通用，而且天然和芯片上的文字一致。

## 改了哪些地方

| 位置 | 改前 | 改后 |
|---|---|---|
| `formatMoney()`（唯一入口） | 用 `currency.symbol` | 用 `currency.code + " "` |
| 汇总卡 / 本月卡 | `CN¥256.02` | `CNY 256.02` |
| 列表主金额 | `CN¥91.74` | `CNY 91.74` |
| 列表副行 | `JP¥981 JPY` | `JPY 981` |
| 金额输入框前缀 | `CN¥` | `CNY ` |
| 汇率页 | `1 人民币 = 1.17 港币` + 右侧 `HKD` | `1 CNY = 1.17 HKD` + 下面小字 `港币` |
| 汇率页未设置行 | `1 人民币 = —— 港币` + 红字 | `1 CNY = —— EUR` + 红字 `欧元 · 未设置，点这里填写` |
| 汇率未填红条 | `港币的汇率还没填` | `HKD 的汇率还没填` |
| 设置页 | `🇨🇳 人民币 · 只改…` | `🇨🇳 CNY · 只改显示，不改账本` |

### 数据库里的 `currencies.symbol` 列现在用不到了

**但不删**。删列要改表结构、升版本、做迁移，为一个显示偏好不值得。
留着，将来若要做"紧凑模式"（`¥188.86`）还能用。

> **通用原则：显示层改主意，别急着动数据层。**

## 顺带修掉的 4 处"不统一"

| # | 问题 | 修法 |
|---|---|---|
| 1 | 三个输入框里，金额和原因下面有提示文字，**日期下面空着** —— 看着像"少了一块" | 日期框下面常驻 `点这里改`；跨年时换成 `2025年` |
| 2 | 汇率页**已设置的行 1 行文字、未设置的行 2 行**，行高参差 | 统一成固定两行：第一行公式，第二行中文名（未设置时变红字提示） |
| 3 | 月份标题 `2026 年 10 月`（带空格），明细写 `10月19日`（不带） | 统一成 `2026年10月` |
| 4 | 设置页底部说明里用了**硬换行 `\n`**，叠上自动折行后出现孤字「显示，」 | 删掉硬换行，交给系统折行 |

> **第 1 条是通用教训：并排的几个控件，装饰性的副文本必须"要么都有、要么都没有"。
> 有一个空着，视觉上就是缺口，人一眼能看出来，但说不清哪里不对。**

## 已知遗留（记录在案）

1. **币种芯片要横滑**：6 个币种在 384dp 里只放得下 4 个，EUR/GBP 要滑出来才看得到，
   而且没有滚动提示。分类芯片行同样。要改的话得缩小芯片（去掉国旗）或改成下拉。
2. **金额输入框为空时，前缀 `CNY` 不显示**（Material 3 的 TextField 行为：
   空且未聚焦时只显示标签）。所以空着的时候看不到币种 —— 靠上面那行芯片来指示。
3. 汇率页说明文字仍会折成两行（只是不再出现孤字）。
