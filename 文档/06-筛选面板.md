## 四、这一轮值得带走的概念

### ① 「用约束消除无效状态」—— 你自己提的，现在用到了组件级

你想出的"起始日期不能早于第一笔记账"启发了我：**这个约束不该在用户选完后再校验，而应该让他根本点不出来**。

官方 `DatePickerDialog` 提供了 `SelectableDates` 接口：

```kotlin
val selectable = object : SelectableDates {
    override fun isSelectableDate(utcTimeMillis: Long) = utcTimeMillis in lowerBound..upperBound
    override fun isSelectableYear(year: Int) = year in ... 
}
val state = rememberDatePickerState(selectableDates = selectable)
```

结果：日历上超出范围的日期**是灰的、点不动**。零校验代码、零错误提示。

> **通用原则：能靠"不让选"解决的，不要靠"选完了再骂"。**

### ② 官方 DatePicker 的时区陷阱

`DatePickerDialog` 给你的 `selectedDateMillis` 是 **UTC 午夜的毫秒数**。

在 UTC+8：
- 你选了 10 月 1 日
- 拿到的是 `2026-10-01T00:00:00Z`
- 如果直接当本地时间用，就变成**本地 10 月 1 日 08:00**
- 只比较日期时没事，但一旦拿它当边界去卡时间戳，**就会差一整天**

正确做法：先按 UTC 取出"是哪一天"，再重新算这一天的**本地**起点/终点毫秒：

```kotlin
fun utcMidnightToLocalDay(utcMillis: Long, startOfDay: Boolean): Long =
    Instant.ofEpochMilli(utcMillis).atZone(ZoneOffset.UTC)
        .toLocalDate().toEpochMillisLocal(startOfDay)
```

> **凡是"跨系统传时间"，第一个要问的就是：这是哪个时区的？**

### ③ 边界条件的处理方式：钳制，而不是报错

用户把"起始"推到"结束"之后怎么办？

- ❌ 弹提示"起始不能晚于结束" → 打断操作
- ✅ **把另一端一起推过去**（钳制）→ 用户永远得不到非法区间

```kotlin
fun onCustomStartChanged(localStartOfDay: Long) {
    customStartMillis = localStartOfDay
    val end = customEndMillis ?: defaultCustomEnd()
    customEndMillis = if (end < localStartOfDay) 那一天结束 else end   // ← 钳制
}
```

区间永远合法 → 永远筛得出东西 → 不会出现"一条记录都没有，用户以为数据丢了"。

### ④ 图标库不够用时：自己画矢量图

`material-icons-core` 只提供约 40 个基础图标（Add/List/Settings/Search/Delete…），**里面没有漏斗**；`material-icons-extended` 那个大集合已停止随版本更新。

解法：`res/drawable/ic_filter.xml` 一个 24×24 的矢量图，几十字节、随主题染色、任何分辨率清晰。

```xml
<path android:fillColor="#FF000000"
      android:pathData="M4,5h16l-6.5,8.5v5.5l-3,-2v-3.5z" />
```

## 五、两个我替你定了语义的地方（需要你确认）

| 项 | 我实现成 | 另一种可能 |
|---|---|---|
| **本周** | 周一为第一天（香港/内地习惯） | 周日为第一天（美式） |
| **本季** | **自然季度**：1-3 / 4-6 / 7-9 / 10-12 月 | 最近 90 天（滚动窗口） |

**「本季」这个差别很大**：现在是 10 月，所以"本季"只含 10-12 月，**9 月的账不算本季**。如果你想要"最近三个月"，那是另一种语义，说一声我改。

### 我自己又犯了一次的错

我在验收脚本里手写了「本年+餐饮 应为 HK$108.00 / 2 笔」，实际是 HK$42.00 / 1 笔 —— **因为去年那条餐饮不属于本年**。代码是对的，我的期望值错了。

> **正确做法：期望值要从数据里算出，不要人肉算。**
> 比如直接跑一句 SQL `SELECT SUM(amountMinor) FROM expenses WHERE categoryId=1 AND strftime('%Y',...)='2026'`
> 拿它当期望，再和界面对比。人脑算边界条件就是会错。
