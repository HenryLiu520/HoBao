## 二、组件到底是什么

一个**跑在别人进程里的界面**。

你的 Activity 跑在 `com.liuhaoran.hobao` 进程里，组件跑在**桌面（launcher）进程**里。
跨进程不能传代码，只能传**描述** —— 所以组件不用 Compose，用 `RemoteViews`。

```
荷包进程                       桌面进程
┌──────────────┐              ┌──────────────┐
│ Room 数据库   │              │  桌面 UI      │
│      ↓       │              │      ↑       │
│ 查数据        │  RemoteViews │  照着图纸画   │
│ 填进"图纸"    │ ───────────→ │              │
└──────────────┘   （跨进程）   └──────────────┘
```

## 三、三个概念

### 概念一：RemoteViews 是白名单，不是"缩水版 Android"

`RemoteViews` 只认这些 View：

```
TextView  ImageView  Button  ImageButton  ProgressBar  Chronometer  AnalogClock
LinearLayout  FrameLayout  RelativeLayout  GridLayout
ListView  GridView  StackView  ViewFlipper  AdapterViewFlipper  TextClock
```

**不在名单里**：`android.view.View`、`Space`、`RecyclerView`、任何自定义 View、任何 Compose。

> **坑**：四宫格的分隔线本来想用 `<View height=1dp>`，结果整个组件渲染失败，
> 钉到桌面时显示 **"Can't load widget"** —— 不是显示错乱，是**加载不了**，logcat 里也没有指向布局的报错。
> 正解：用 1dp 高、带背景色的空 `TextView` 冒充。

Jetpack Glance 让你用 Compose 语法写组件，但**编译产物仍是 RemoteViews**，白名单还是那套。

### 概念二：组件是快照，不是活的

```
❌ 错的想法：组件"订阅"了数据库，数据一变它自己变
✅ 对的模型：组件是一张照片，你什么时候重拍，它就什么时候更新
```

系统能帮的只有 `updatePeriodMillis`，而它**最小 30 分钟**、**不保证准时**、**省电时会推迟**。

所以正确做法：**app 每次写完数据，主动推一次**。

```kotlin
object WidgetUpdater {
    fun refresh(context: Context) {
        val manager = AppWidgetManager.getInstance(context)
        val ids = manager.getAppWidgetIds(ComponentName(context, HoBaoWidgetProvider::class.java))
        if (ids.isEmpty()) return          // 桌面上没有组件 → 什么都不做
        context.sendBroadcast(Intent(...).apply {
            action = AppWidgetManager.ACTION_APPWIDGET_UPDATE
            putExtra(AppWidgetManager.EXTRA_APPWIDGET_IDS, ids)
        })
    }
}
```

调用点：`addExpense` / `deleteExpense` / `importBackup` 之后各一次。

### 概念三：点击靠 PendingIntent

组件在你的进程之外被点，你没法挂回调函数。`PendingIntent` 是：

> **把一张"未来要执行的意图"交给系统保管，谁点了就由系统代你执行。**

三个属性：**目标**（哪个 Activity）、**身份**（用谁的权限）、**有效期**。
必须带 `FLAG_IMMUTABLE` —— 否则别人能篡改你的意图。

⚠️ **三个区域要三个不同的 `requestCode`**：
`getActivity` 用「requestCode + Intent」判断是不是同一个 PendingIntent，
两个都用 0 的话，系统会认为是同一个，其中一个的点击会被吞掉。

```kotlin
views.setOnClickPendingIntent(R.id.cell_today, openApp(context, requestCode = 0))
views.setOnClickPendingIntent(R.id.cell_open,  openApp(context, requestCode = 0))  // 同目标可共用
views.setOnClickPendingIntent(R.id.cell_new,   PendingIntent.getActivity(context, 1, Intent(QuickAddActivity), ...))
```

## 四、「＋ 新建」为什么是个悬浮小窗，不是组件内的输入框

**平台硬限制：组件里不能打字。**

`EditText` 不在 RemoteViews 白名单里，组件也**调不出输入法** ——
输入法属于 app 进程，组件跑在桌面进程里，够不着。

所以「原因」这一栏，在组件内部**物理上做不到**输入中文。

解法：一个**透明背景的 Activity**。

```xml
<style name="Theme.HoBao.Popup" parent="android:Theme.Material.Light.NoActionBar">
    <item name="android:windowIsTranslucent">true</item>       <!-- 能看到底下 -->
    <item name="android:windowBackground">@android:color/transparent</item>
    <item name="android:backgroundDimEnabled">false</item>      <!-- 系统 dim 关掉，改由 Compose 画 -->
</style>
```

系统 `backgroundDim` 是**整屏均匀压暗**，没法只压卡片外面；
关掉它，由 Compose 画一层 `Color.Black.copy(alpha = 0.45f)`，点这层 = 取消。

**两个必须做对的细节：**

1. **吞掉卡片内部的点击**
   ```kotlin
   Box(Modifier.clickable { onDismiss() })          // 外层：点外面取消
   Box(Modifier.clickable(indication = null) {})    // 卡片：空 lambda 吞掉点击
   ```
   不吞的话，点卡片任何地方都会触发外层，窗口直接关掉。

2. **存完才关窗**
   ```kotlin
   vm.addExpense(..., onSaved = onDismiss)
   ```
   先 `finish()` 再存的话，Activity 一销毁 `ViewModel` 就被清掉，
   `viewModelScope` 里的协程**被取消** —— 这笔账丢了，而且**不报错、不闪退**。

小窗复用 `ExpenseViewModel`，「原因为空→用分类名」「冻结汇率快照」这些规则**一处都不用抄**。

### 金额和原因用同一个键盘

都是系统输入法。金额框 `KeyboardType.Decimal` 会直接给数字键盘，原因框给普通文字键盘。

> 一开始做的是**自绘 3×4 数字键盘**，用户否了：「数字不要键盘，也用跟原因一样的键盘就行」。
> 自绘键盘的唯一好处是位置可控，代价是**多一套要维护的输入逻辑**，而且和系统键盘的交互不一致。

## 五、踩的坑

| # | 现象 | 原因 | 解 |
|---|---|---|---|
| 1 | 钉组件时显示 **Can't load widget** | `<View>` 不在 RemoteViews 白名单 | 用空 `TextView` 冒充弹簧/分隔线 |
| 2 | 组件中间一大块空洞 | `layout_weight=1` 把内容劈成两半 | 根布局 `gravity="center_vertical"` |
| 3 | 金额变三位数就被截成 `CNY 117...` | 2 格宽只有约 100dp，21sp 放不下 | `autoSizeTextType="uniform"` 11–20sp 自适应 |
| 4 | 选择器预览是 `CNY 0.00 / —` | `previewLayout` 指向真实布局，显示的是占位文字 | 单独做 `widget_preview.xml` 放示例数据 |
| 5 | 加完账组件数字不变 | `WidgetUpdater` 只推了一个 provider | 每个 provider 单独推 |
| 6 | `⌫` 显示成带叉的方框 | 字符 U+232B 在 Roboto 里**没有字形** | 自绘矢量图（自绘键盘已删，此坑留档） |
| 7 | 遮罩后面露出 app 的设置页 | 悬浮 Activity 和主界面共享任务栈 | `android:taskAffinity=""` 独立成任务 |
| 8 | `onUpdate` 读库偶尔得到旧数据 | 广播只有几秒寿命 | `goAsync()` + `finally { finish() }` |

### 测试环境的三个坑（真机没有）

- **`install -r` 后 launcher 留着旧 RemoteViews 视图**，桌面上组件"消失"（dumpsys 里仍在）。
  重启 launcher：`am force-stop com.google.android.apps.nexuslauncher`。
- **组件的无障碍节点 `package` 是荷包自己**（RemoteViews 用 app 包名 inflate），不是 launcher。
- **模拟器开了硬件键盘时，会浮出一个竖条工具条**（麦克风/退格/方向/表情），
  它**盖住卡片最左边那一列** —— 点第一个分类芯片会点空，
  于是「没选分类 → 保存键禁用 → 怎么点都没反应」，看起来像保存坏了。

## 六、按 Google 最新规范美化（Android 12+）

**核心是「内外两层圆角」** —— 这是 Android 12 之后组件的视觉语言：

```
┌──────────────────────────┐  ← 外壳：system_app_widget_background_radius
│  ╭────────────────────╮  │
│  │      今日开销        │  │  ← 内格：system_app_widget_inner_radius
│  │      CNY 42.59     │  │
│  ╰────────────────────╯  │
│  ╭─────────╮ ╭────────╮  │
│  │ ↗ 打开  │ │ + 新建 │  │  ← 格子之间用**空隙**分开，不画分隔线
│  ╰─────────╯ ╰────────╯  │
└──────────────────────────┘
```

### 1. 两个圆角都读系统的值

| 用在哪 | 资源 |
|---|---|
| 外壳 | `@android:dimen/system_app_widget_background_radius`（API 31+，Pixel 上 28dp）|
| 内格 | `@android:dimen/system_app_widget_inner_radius`（API 31+）|

**为什么不能写死**：Android 12 起，桌面会把组件裁成**它自己的**圆角形状。
你写 24dp、系统裁 28dp → 四个角露出一圈脏边；反过来你的圆角会被裁掉一半。

内圆角那条还有个硬性前提，官方原话：

> "System-provided radius for inner views on app widgets that are positioned **8dp within** the widget background view."

所以**内边距必须也是 8dp** —— 否则内外两个圆角曲率不同心，看着就是"有点歪"。

### 2. 内格要比外壳亮/暗一档

**圆角只有在两层颜色有差的时候才看得出来。** 所以配色分三级：

| 层 | 浅色 | 深色 |
|---|---|---|
| 外壳 `widget_bg` | `#F3F0FA` | `#17161B` |
| 内格 `widget_cell` | `#FFFFFF` | `#2A2930` |
| 文字 / 图标 | `#63606A` `#1B1B21` `#46528C` | `#C9C5D0` `#E6E1E9` `#C3C9F0` |

深色模式下外壳更深、内格略亮 —— **层次关系保持，不是简单把颜色调暗**。

### 3. 用空隙代替分隔线

以前是「1dp 横线 + 1dp 竖线」，现在是 **6dp 空隙**。

> 分隔线是**表格**的语言；空隙 + 各自圆角才是**卡片**的语言。

### 4. 内格背景 = 圆角 + 水波纹，必须写在同一个 drawable 里

```xml
<ripple xmlns:android="http://schemas.android.com/apk/res/android" android:color="#2E46528C">
    <item android:id="@android:id/mask">   <!-- mask 决定波纹被裁成什么形状 -->
        <shape>
            <solid android:color="#FFFFFFFF" />
            <corners android:radius="@dimen/widget_inner_radius" />
        </shape>
    </item>
    <item>
        <shape>
            <solid android:color="@color/widget_cell" />
            <corners android:radius="@dimen/widget_inner_radius" />
        </shape>
    </item>
</ripple>
```

⚠️ 一个 View 只能有**一个** `background`，所以**不能**再叠
`?android:attr/selectableItemBackground` —— 两者会互相覆盖（圆角没了，或者波纹没了）。

### 5. 动作行固定高度，让信息区吃剩余空间

```
信息格   layout_weight = 1      （跟着组件变大变小）
动作行   layout_height = 44dp   （固定）
```

2×2 时如果两行都用 `weight=1`，动作格会被拉成**又高又窄的药丸**，不像按钮。

### 6. 深色模式 + 平滑过渡

- `values/colors.xml` + `values-night/colors.xml` 两套同名颜色，系统按 uiMode 自动选
- 根布局 `android:id="@android:id/background"` → Android 12+ 靠它做「组件→app」的连续动画
- 图标用矢量 drawable + `android:tint`，同一份素材复用到两套配色

### 7. Material You 动态取色：**没做**（有意的）

官方给的路是根布局套 `android:theme="@style/Theme.Material3.DynamicColors.DayNight"`，
再用 `?attr/colorPrimaryContainer` 取色。

但 `Theme.Material3.DynamicColors` 来自 **Material Components for Android**（View 体系那个库），
本项目是纯 Compose + Material3，**没有引入它**。

替代方案是直接引 `@android:color/system_accent1_*`，
但那些色阶哪一档是浅、哪一档是深很容易搞反，而这个组件只有四个色块 —— **收益小于风险**。

> 工程判断：**不是"官方有什么就必须用什么"，是"这一处值不值得"**。

## 八、锁屏组件：不是第二套代码

同一个 `AppWidgetProvider`，在说明书里声明：

```xml
android:widgetCategory="home_screen|keyguard"
```

系统就会让它在锁屏上也出现。但历史很曲折：

| 版本 | 状况 |
|---|---|
| Android 4.2 – 4.4 | 有锁屏组件 |
| Android 4.4 之后 | **移除** |
| Android 14 | 以**平板**身份回归 |
| Android 15+ | 才开放给**手机**，且需用户在锁屏设置里手动开 |

**厂商差异极大**：三星 One UI 的锁屏组件基本只给自家 app 用，第三方 widget 能不能放上去要实测。

> 当前决定：**先只做桌面**（`widgetCategory="home_screen"`），锁屏以后单独试。
