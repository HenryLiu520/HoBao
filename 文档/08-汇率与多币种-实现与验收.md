## 三、三个能带走的概念

### ① 冻结的是汇率，不是结果

规格里我本来打算把「折算后的人民币金额」也存一列（`amountCnyMinor`）。
**实现时去掉了。**

理由：汇率快照已经冻结了，折算值由 `(amountMinor, minorUnits, ratePerCny)` **唯一确定**。
今天算、明年算、换台机器算，结果一模一样。

存两份 = 同一件事记两遍。哪天有人只改了一边，两份数据打架，而且**不会报错**。

> **只存"不可推导的输入"，别存"能算出来的结果"。**
> 除非是为了查询性能（那叫物化，是另一个理由）。

### ② 两层账本，各有各的规矩

```
账本层（数据库）  ratePerCny 快照 → 折算成人民币 → 永不变
显示层（界面）    人民币 × 当前汇率 → 你选的报告币种 → 随汇率变
```

于是这两句话**同时成立**：
- 「改了汇率不影响已记的账」→ 说的是账本层
- 「切币种总额会变」→ 说的是显示层

### ③ 方向不同，算法不同（乘 vs 除）

| 方向 | 写入时（外币→人民币） | 显示时（人民币→外币） |
|---|---|---|
| `ratePerCny` = 1 CNY 等于多少外币 | **除法** | **乘法** |

**除法只在写入时做一次，且整个表达式算完才舍入一次。**
如果先求倒数（1 外币 = 多少人民币）再乘，就多舍入一次，误差翻倍。

```kotlin
// ✅ 一次算完，一次舍入
amountMinor * 100.0 / (pow10(minorUnits) * ratePerCny)
// ❌ 先取倒数：多一层舍入，而且 rate=0 时直接除零
```

## 四、实现踩的两个真坑

### 坑 1：`fallbackToDestructiveMigration` 不会触发 `onCreate`

表删了、重建了、**初始数据一条没播**。界面上分类空白、币种空白 —— 看起来像功能坏了。

```kotlin
override fun onCreate(db) = seed(db)                 // 只在"文件从无到有"时
override fun onDestructiveMigration(db) = seed(db)   // 重建表之后要自己补
```

### 坑 2：把 `val x: Boolean get() = ...` 写进了构造参数列表

```kotlin
data class CurrencyEntity(
    ...
    val isBase: Boolean get() = code == "CNY",   // ❌ 语法错
)
```
KSP 报的错是 `[MissingType]: references a type that is not present`，完全看不出真正原因。

**正确写法**：放类体里。Room 会自动忽略"没有 backing field 的计算属性"，不会当成列。

```kotlin
data class CurrencyEntity(...) {
    val isBase: Boolean get() = code == "CNY"     // ✅
}
```

> **Room 的规矩：构造参数 = 数据库的列。算出来的东西永远别放构造参数里。**

## 五、验收（期望值全部由 SQL 算出，没手算）

测试数据：CNY ¥50.00 ＋ HKD HK$100.00（汇率 1.09）＋ JPY ¥980（汇率 20.80）

```sql
SELECT SUM(Round(amountMinor*100.0/(CASE c.minorUnits WHEN 0 THEN 1.0 ELSE 100.0 END)/e.ratePerCny))
FROM expenses e JOIN currencies c ON c.code=e.currencyCode;
-- 18886 分
```

### 我又算错一次（第三次了）

验证脚本里我写「切到港币应为 HK$2.27」—— 把"分"又除了一次 100。
界面显示 HK$226.63 是对的。

> **这已经是同一个错误的第三次。** 结论很明确：
> **任何带"分/元""分/港币"换算的期望值，必须让程序算，人肉算必错。**

## 六、已知取舍（记录在案，不改）

1. **2 位小数**：英镑这类"1 单位很贵"的币种约有 3.6% 误差；以后加科威特第纳尔这类会更差
2. **币种芯片行要横滑**：6 个币种在 384dp 里只放得下 4 个，欧元/英镑要滑出来才看得到
3. **`fallbackToDestructiveMigration`**：现在删库重建，**上线前必须换成真正的 Migration**，否则用户升级一次丢一年账
4. **报告币种存 SharedPreferences**：只一个 key，够用；设置项多起来再换 DataStore
