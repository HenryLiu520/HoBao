## 二、汇率输入方向（我补的最后一块）

数据模型里的字段叫 `rateToHkd`，语义是「**1 单位该币种 = ? 港币**」。

所以界面上填的是：

| 币种 | 填什么 | 例子 |
|---|---|---|
| CNY | 1 人民币 = ? 港币 | `1.09` |
| JPY | 1 日元 = ? 港币 | `0.05` |
| USD | 1 美元 = ? 港币 | `7.80` |

这和你说"1 人民币 = 多少"**完全一致**（对人民币来说就是同一个数），
而且**不需要取倒数** —— 取倒数就是除法，除法会引入额外误差和除零风险，这里可以完全避免。

## 三、核心不变式（最重要的一节）

> **同一条账单，它的港币等值一旦写入就永不改变。**
> **界面上看到的任何其它币种数字，都是这个值按"当前汇率"临时换算出来的。**

### 算法

```
记账时（写入，只做一次）：
  hkdCents = round( amountMinor / 100 × rateToHkd × 100 )
           = round( amountMinor × rateToHkd )          ← 统一两位小数后这就是简化式

冻结进数据库：amountMinor、currencyCode、rateToHkd

查总额：
  港币合计   = SUM(hkdCents)                              ← 永远不变
  人民币合计 = 港币合计 × (当前 1 HKD = ? CNY)             ← 随汇率变，但这是"换算"
```

### 两层结构

| 层 | 是什么 | 变不变 |
|---|---|---|
| **账本层**（数据库） | 每条账单的 `hkdCents` | ❌ 永不变 |
| **显示层**（界面） | 按当前汇率折成报告币种 | ✅ 随汇率变 |

用户改日元汇率 → 账本层不动 → 港币总额一分不动。
用户切报告币种 → 账本层不动 → 人民币总额按今天牌价变，但那是"换算"不是"改账"。

### 必须给用户的两个信号

```
① 汇总卡下方小字：  按今日汇率换算 · 1 HKD ≈ 0.92 CNY
② 改完汇率弹一句：  已更新。此前 37 笔记录按各自记账时的汇率计算，合计不变。
```

## 四、你选的两条，代价记录在案

### ① 2 位小数：日元会有约 2.5% 的系统性误差

| 币种 | 真实值（量级） | 填 2 位 | 误差 |
|---|---|---|---|
| 美元 | 7.80 | 7.80 | 0% |
| 人民币 | 1.09 | 1.09 | 0% |
| **日元** | **0.0513** | **0.05** | **≈2.5%** |

980 円 的拉面会记成 HK$49.00，真值约 HK$50.30。

**另外**：如果以后加韩元（0.0057）、印尼盾、越南盾这类弱币，2 位小数会直接爆掉
（0.0057 → 0.01，误差 75%；更小的直接四舍五入到 0.00，账全变零）。
**加新币种时记得回头复查这条。**

### ② 统一两位小数：`currencies.minorUnits` 作废

日元会显示成 `¥980.00`。数值上前后一致（存 98000 分、显示除以 100），
但日元的最小单位本来就是 1 円，`980.00` 在日语文境里是错的写法。

**保留这个决定的唯一好处是"所有币种一套代码"**，代价是显示不符合日元习惯。

## 五、未设汇率的判定

沿用现有的播种值：`rateToHkd = 0.0` 表示**未设置**。

```
isRateSet(currency) = currency.rateToHkd > 0.0
```

- 记账页：选中未设汇率的币种 → 保存按钮禁用 + 一行提示"请先在设置里填 XX 汇率" + 一个跳转按钮
- 汇率输入框：拒收 `0`、负数、空值（`0` 是"未设置"的哨兵值，不能当有效汇率）

## 七、验收标准（先写在这里，做完对账）

用 SQL 从数据库算期望，**不人肉算**：

```sql
-- 期望的港币合计
SELECT SUM(CAST(ROUND(amountMinor * rateToHkd) AS INTEGER)) FROM expenses;
```

然后对比：
- 港币口径合计 == 界面切到港币时的合计
- 人民币口径合计 == 港币合计 × 当前 CNY 汇率（容差 1 分）
- 改一个汇率后，**已存在记录的 hkdCents 逐条不变**
- 未设汇率的币种 → 保存按钮禁用
- 崩溃 0
