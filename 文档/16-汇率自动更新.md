# 16 · 自动联网更新汇率（v1.0.0）

> 2026-10-19 · 汇率从「手填常量」变成「每日同步 + 缓存降级」

---

## 一、需求

原来设置里那个「自动联网更新」是灰的，写着「即将推出」。这一版把它做成真的：

- 打开开关 → 后台**每天**拉一次
- 也可以点「立即更新」手动触发
- 拉不到时**不能假装成功** —— 记账 app 用旧汇率算钱比报错危险

`fawazahmed0/currency-api`（无 key、免费、任意基准、支持历史日期）。

## 三、四个关键决定

### 1. base 用 CNY，一次换算都不做

项目的核心字段 `ratePerCny` 语义是「1 CNY = 多少外币」。拿 CNY 当 base 时，
响应里的 `cny.usd` **直接就是这个数** —— 零换算 = 零精度损失 = 零方向搞反的风险。

三角换算 `rate(A→B) = (B/base) ÷ (A/base)` 仍然实现了（`ForexRateTable.rate`），
但那是给「将来换 base」留的接口，现在一次都没用上。除法用 `BigDecimal`，保留 12 位。

### 2. 汇率**不截断到两位**

手填的汇率限两位，是用户自己定的输入规则。API 给的是 8~9 位有效数字。

> 把 USD 截成 `0.15`，每笔美元账的折算误差 **0.44%**（100 美元差 4 毛 4）。
> 所以**存全精度，显示仍两位** —— 界面上看不出区别，但账算得对。

### 3. 缓存放 SharedPreferences，不建 Room 表

加一张表 = 改 schema = 撞上 `fallbackToDestructiveMigration` = **用户数据全清**。
为 5 条缓存付这个代价不值。

缓存的 key 是**响应里的 `date`**，不是本地时间 —— 设备时钟不准、时区不同都不会误判。
写入格式 `YYYY-MM-DD`。

### 4. 同步结果分四种，不能合并

```kotlin
sealed interface ForexSyncOutcome {
    data class Fresh(val table: ForexRateTable)   // 刚联网抓到
    data class Cached(val table: ForexRateTable)  // 冷却期内，用内存那份
    data class Stale(val table: ForexRateTable)   // 两个源都挂了，退回旧缓存
    data class Failed(val error: Throwable?)      // 没网且从来没成功过
}
```

`Stale` 单独存在的理由：**有旧数据可用，但必须让用户知道这是旧的**。
界面会写「网络不可用，用的是 2026-10-18 的数据」，而不是装成刚更新过。

## 四、数据流

```
ForexScheduler（开关）
   ├─ 打开 → WorkManager 入队（每 24h，要求有网）
   └─ 界面「立即更新」→ ViewModel.syncForex()
                     ↓
              ForexSyncer.sync()
                     ↓
   ForexClient.fetch()  ── 主源失败 → 备源
                     ↓
   ForexRateTable（date + 5 个币种，crypto 已被白名单挡掉）
                     ↓
   ① ExpenseRepository.applyForexTable()  → 写 currencies 表（界面立刻能看到）
   ② ForexCache.save()                    → 落盘（下次冷启动有东西可用）
```

写库复用 `CurrencyDao.updateRate(code, rate, at)` —— 和手填汇率**同一条语句**，
所以「改汇率不动历史账单」的性质自动成立（账单存的是各自的快照，根本不读这张表）。

## 七、踩的坑：`Could not resolve junit`（其实跟 junit 无关）

跑单元测试时一直报 `Could not resolve junit:junit:4.13.2`，但 junit 本身完全正常。

真凶：

1. KSP 的 **plugin marker**（`com.google.devtools.ksp.gradle.plugin`）在 Maven Central 上
   **只有 POM、没有 jar**（marker 就是个空壳）
2. **阿里云镜像对它返回 502 而不是 404**
3. 502 属于 IO 错误 → Gradle 把整个仓库标记为不可用 → **报出的是下一个依赖 junit**
4. 于是排查方向被带跑

试过 `exclude` 这个 marker，结果连 KSP 插件自身的解析也被排掉，报 `Plugin ... was not found`。

**解法**：把 `google() / mavenCentral() / gradlePluginPortal()` 排到阿里云**前面**。
Central 的 POM 里写了 packaging=pom，Gradle 就不会去要 jar，问题从根上消失。

> 代价：中央仓库直连，可能比镜像慢一点。
> 想换回镜像顺序的话，**换完先跑一次 `testDebugUnitTest`** ——
> 只看 `assembleDebug` 通过是发现不了的。
