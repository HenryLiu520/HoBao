# 补记日期 + 原因回退分类名（阶段 4 · 第 2.5 项）

> 需求（用户原话）：添加的时候可以选日期，默认是今天；如果没写原因，原因就默认跟分类名字一样。
> 验收：**4/4 通过，崩溃 0**

---

## 一、这个改动为什么比看起来重要

`createdAt` 原来是这样产生的：

```kotlin
val now = System.currentTimeMillis()   // 系统说什么就是什么 → 这是「事实」
```

现在它变成了：

```kotlin
addExpense(..., createdAt = 用户选的某一天)   // 用户说什么就是什么 → 这是「输入」
```

**一旦一个字段从"事实"变成"输入"，它就需要边界、校验和默认值。**

而 `createdAt` 恰好同时被**四个功能**依赖：

| 依赖它的功能 | 出错的后果 |
|---|---|
| 排序 | 补记的账跑到列表最上面/最下面 |
| 按月分组 | 月小计算错 |
| 时间筛选（今天/本周/本月/本季/本年） | 筛出错误的记录 |
| 本月支出卡片 | 首页数字错 |

**一个字段被四个功能依赖 → 它的每一处取值都必须想清楚。** 这是这次改动真正的分量。

## 二、我替你定的 3 件事（不对就说）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **补记时保留当前的时分秒，只换年月日** | 用那天 00:00 会让同一天内的账顺序乱掉；而且某些时区午夜有夏令时切换。选今天时直接用"现在"，连毫秒都是真实的记账时刻 |
| 2 | **未来的日期禁用**（日历上灰掉点不动） | 还没花出去的钱记不了账。这是「用约束消除无效状态」的第三次应用 |
| 3 | **存完一笔，日期自动复位到今天** | 见下面第四节，这是补记功能最经典的坑 |

---

## 三、三个能带走的概念

### ① 新增功能不一定要增加操作成本

"记一笔"原来就是 3 次触达（金额 → 原因 → 分类 → 保存）。
加了币种、加了日期，**还是 3 次** —— 因为默认值选对了：

- 币种默认 = 报告币种
- 日期默认 = 今天
- 原因默认 = 分类名

> **判断一个功能"重不重"，不看它有几项，看它有几项需要用户动。**
> 加十个默认对的字段，手感上等于没加。

### ② 默认值必须是「可见的」

"原因留空就用分类名"这条规则，我把它**写在了输入框下面**：

```
原因
[_______________]
留空则用分类名
```

而不是偷偷在保存时替换。区别在哪：

- 写出来 → 用户知道不填会发生什么，想改就直接改
- 藏起来 → 用户某天发现"我明明没写原因，怎么变成餐饮了"，以为出 bug

> **隐藏的默认值不是"智能"，是"让人猜"。**

### ③ 数据规则要放在数据层，不是界面层

```kotlin
// ✅ 放在 ViewModel.addExpense 里
val finalReason = reason.trim().ifEmpty { categoryName ?: "未分类" }
```

为什么不在界面上判断空字符串就完事？

因为**这是数据的规则，不是某个界面的规则**。将来做 CSV 导入，导入的账也要遵守"原因为空用分类名"——规则放在 ViewModel，导入自动继承；放在界面，以后每加一个入口就要抄一遍，迟早漏。

> **同样一条规则，放在越靠数据的地方，被复用的次数越多、被漏掉的次数越少。**

## 四、补记功能最经典的坑：日期不复位

```
用户操作：补记一笔 9 月 15 日的账 → 保存
          ↓
接下来：想记今天的午饭
          ↓
如果日期不复位：这笔午饭被记到了 9 月 15 日
          ↓
用户三天后才发现总额不对，而且已经记了十几笔
```

**这个 bug 不会报错、不会闪退，只会安静地把账记到错误的月份。**

处理方式（两条一起做）：

```kotlin
pickedUtcMillis = LocalDate.now().toUtcMidnightMillis()   // ① 复位
snackbar("已记下 CN¥30.00 · 9月15日")                      // ② 明确告诉用户"这笔记到哪天"
```

第②条同样重要：**补记之后必须让用户看到"记到哪一天了"**，否则他就得自己去列表里翻。

## 六、布局改版：日期做成第三个输入框（用户要求）

**改前**：金额 + 原因 一行，日期单独一行做成文字按钮
**改后**：**金额 / 原因 / 日期 三个框排一行**，日期框长得和左边一模一样，点它弹日历

```
[ 金额    ] [ 原因    ] [ 日期    ]
 两位小数    留空用分类名   10月19日
```

宽度分配（352dp 可用）：金额 112dp ／ 原因 112dp（weight）／ 日期 112dp，间距 8dp。

### 为了"一模一样"踩的两个点击坑

**坑 A：`readOnly = true` + 外层 `clickable` —— 没用**
readOnly 的输入框仍然会吃掉触摸去拿焦点，点击到不了外层。
（Compose 的指针事件先给最里层的子节点，外层 `clickable` 抢不到。）

**坑 B：在输入框上盖一层透明可点区域 —— 点击能用了，但挡住了无障碍树**
后果不止一个：uiautomator 读不到这个框的文字（自动化测试找不到它）、
TalkBack 也读不到（读屏用户用不了它）。**两个问题同一个原因。**

**正解：`enabled = false` + 自定义 colors**

```kotlin
Box(modifier = modifier.clickable(onClick = onClick)) {
    OutlinedTextField(
        value = value, onValueChange = {}, enabled = false,
        colors = OutlinedTextFieldDefaults.colors(
            disabledTextColor = onSurface,          // 把禁用色覆盖成正常色
            disabledBorderColor = outline,
            disabledContainerColor = Color.Transparent,
            disabledSupportingTextColor = onSurfaceVariant,
        ),
        ...
    )
}
```

禁用组件**不消费触摸** → 点击自然落到外层；同时它**仍在无障碍树里** → 文字读得到。

> **通用教训：想给一个"看起来能编辑"的东西改成"只能点"，优先让它禁用 + 换皮，
> 而不是加一层遮罩。遮罩会连带挡住无障碍树。**（Google 自己的 `ExposedDropdownMenu` 也是这么做的）

### 顺带修的两处

1. 支持文案压短：`最多两位小数` → `两位小数`、`留空则用分类名` → `留空用分类名`。
   三个框并排后宽度只有 112dp，**提示一换行，三个框高度就不齐了**。
2. 日期框里只放 `10月19日`，**年份不进格子**（塞进去会把日子挤掉）；
   跨年时在下面那一行小字里补 `2025年`。

## 七、还没管的边界（记录在案）

1. **补记的账在列表里的位置**：按 `createdAt` 排序，所以补记的 9 月账会排到 9 月那段去 —— 这是**正确**的，但它不会"跳到顶部"提醒你刚记了一笔。如果你希望"刚记的账总在最上面"，那排序键就得换成 `updatedAt`，跟"按月分组"会打架。先不动。
2. **跨年补记**：日历年份可选 2000 到今年。选到其它年份时，框里仍是 `10月5日`，
   年份显示在框下面那行小字（`2025年`）—— 因为格子只有 112dp，塞进年份会把日子挤掉。
3. **编辑已有账单时改日期**：编辑功能还没做，做的时候要复用同一个 `createdAtFor()`。

## 八、三个框的标签统一到左上角（用户要求）

**用户原话**：「还有日期和原因金额的不统一，统一改成左上角，跟日期一样那种」

### 问题出在哪

Material 3 的 `OutlinedTextField` 自带 label，它的位置取决于**隐藏状态**：

| 字段状态 | 标签位置 |
|---|---|
| 空 + 未聚焦 | **缩在框内、垂直居中**（看起来像占位符） |
| 有内容 或 已聚焦 | **飘到左上角的边框上** |

所以三个框并排时：日期框有值 → 标签在左上角；金额和原因还空着 → 标签在框正中间。
**一眼就看得出不齐，但很难说清哪里不对。**

### 修法：三个框统一自己画标签

不在 TextField 里用 `label`，而是套一层 `FieldFrame`：

```kotlin
private val LABEL_LIFT = 8.dp
```

| 步骤 | 做法 |
|---|---|
| 1 | TextField 加 `Modifier.padding(top = 8.dp)` → 边框线正好落在 y = 8dp |
| 2 | 标签 `Text` 画在 y = 0，字高约 16dp → **垂直中线正好 8dp，压在边框线上** |
| 3 | 标签加一块 `background(colorScheme.background)` → 把底下的边框线遮掉，做出"骑在线上开了缺口"的效果 |
| 4 | `padding(start = 12.dp)` + 文字内边距 4dp → 文字从 16dp 开始，和其它字段的文字左对齐 |
| 5 | `FieldFrame` 可选传 `onClick` → 日期框直接把点击交给外层容器（TextField 设 `enabled = false`，不消费触摸） |

**关键好处：标签位置不再依赖"有没有值"。** 空着、有值、聚焦、失焦，四个状态下标签一动不动。

### 改完冒出来的新问题（已修）

标签从框内挪走之后，金额框空着时里面只剩一个孤零零的 `CNY` 前缀 ——
**看起来像已经填了内容**。

修法：前缀只在有内容时提供。

```kotlin
val amountPrefix: (@Composable () -> Unit)? =
    if (amountText.isEmpty()) null else { { Text("${entry?.code ?: "CNY"} ") } }
```

空框就该看起来是空的。有内容时显示 `CNY 12.5`，一眼知道这笔记的是什么币种。

## 九、表单改版：两行两列 + 货币做成第四个框

**用户要求**：
1. 把多余的注释删了（金额、原因下面的提示文字）
2. 货币选择挪到日期左边，点进去能选具体货币，一行一个币种、带汇率和国旗、最右边一个单选点

### 为什么不排成一行四个

可用宽度 **352dp**（屏宽 384 − 左右边距 32），四框三缝（8dp×3 = 24）后每框只剩 **82dp**。
实测最小需求：

| 框 | 最小宽度 | 说明 |
|---|---|---|
| 金额 | **102dp** | 前缀 `CNY ` + 数字 |
| 日期 | **100dp** | `10月19日` 六个字符 + 内边距 |
| 货币 | 62dp | `CNY` |

三个就 264dp，加上间距只剩 **70dp 给原因框** —— 只能看到 4 个字。

**改成两行两列**，每框 **172dp**：

```
[ 金额        ] [ 原因        ]
[ 货币   CNY ▾] [ 日期 10月19日 📅 ]
```

货币正好在日期左边，四个框同一套 `FieldFrame`，宽度、标签位置、高度完全一致。

### 顺带删掉的东西

| 删掉 | 影响 |
|---|---|
| 金额下方「两位小数 / 金额取整」 | 无 —— 输入不合法时仍会显示「格式不对」+ 红边框 |
| 原因下方「留空用分类名」 | ⚠️ **规则本身没变，但界面上看不到了** |
| 日期下方「点这里改」 | 无 —— 右侧加了日历图标，可点性靠图标表达 |
| 顶部整行币种芯片 | 被「货币」框取代，页面反而少了一行 |

**⚠️ 唯一有代价的一条**：原因留空会自动用分类名，这条规则现在没有任何地方提示。
如果哪天用户问"我没写原因怎么变成餐饮了"，就把它加回来 —— 但**加在框里面当 placeholder**，
而不是加在框下面当注释。

### 可点性的表达

两个"只能点"的框都加了右侧图标：

| 框 | 图标 | 含义 |
|---|---|---|
| 货币 | ▾ `ArrowDropDown` | 点开是一个列表 |
| 日期 | 📅 `DateRange` | 点开是日历 |

图标本身不同不是"不统一" —— **位置、大小、对齐完全一致，只有语义符号不同**，
这跟文字内容不同是一回事。

### 货币弹层（`CurrencyPickerSheet`）

一行一个币种，`ModalBottomSheet`：

```
🇭🇰  HKD  港币
     1 CNY = 1.17 HKD                    ⦿
🇪🇺  EUR  欧元            ← 灰掉
     未设置汇率，不能记账                 ○（禁用）
```

- 汇率没填的币种**灰掉且不可选**（跟"汇率没填不能记账"的规则保持一致）
- 选完自动关闭弹层
- 人民币那行写「账本基准」而不是汇率 1.00
